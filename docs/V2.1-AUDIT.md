- **react-native-chart-kit 6.12 keys every gridline, label and dot with `Math.random()`.** So any chart re-render remounts every SVG node.

---

## Bottom line

**At today's 46 sessions the app is not slow.** Most perf items cost single-digit milliseconds today.

The things you would actually notice now are **touch and feel bugs**:
- the first tap is swallowed while the keyboard is up
- the frame card bounces during a game
- Reference resets every time you open it
- Discard on the Resume sheet deletes the draft in one tap
- several controls are under 44pt

The **plumbing items** are fine today but grow with every season of data: backup rewrites, re-parsing everything to detect "no change", off-screen Stats reloads. Fixing them now is cheap insurance.

## Batch 1 — Feel (Level 1)

### P1 — MUST — With the keyboard up, the first tap on any other control only closes the keyboard [C]
*Sources: A6-1, A2-2, A3-1, A5-6*

Only `log-frames.tsx:1005` sets `keyboardShouldPersistTaps`. Example: type a score, then tap Ball / Add game / Submit / Edit Frames / Save Ball / a card header → nothing happens until a second tap.

The ScrollViews missing it:
- `LogPage.tsx:1023`
- `EditSessionModal.tsx:343`
- `SettingsContent.tsx:579`
- `reference/index.tsx:390`
- `SignalsTab.tsx:206`, `:308`
- `PocketDiagnosticsTab.tsx:279`, `:323`
- (PatternsTab is hidden)

**Fix:**
- Add `keyboardShouldPersistTaps="handled"` to each.
- With "handled", a tap a child handles does **not** close the keyboard. So add `Keyboard.dismiss()` to the handlers that should close it: type pills, Lanes, Edit Frames.
- In the Edit sheet, dismiss *before* opening Edit Frames. Otherwise the score field's `onEndEditing → confirmScoreOverride` alert fires as the sheet closes.

**[device]** Check that each of those controls responds to the first tap with the keyboard up.

### P2 — MUST — "Discard" on the Resume sheet deletes the draft + in-progress game in one tap [C]
*Sources: A6-2, A6-16*

`LogPage.tsx:1396` `onPress={discardDraft}` → `:763-771` writes a null draft and clears FRAMES_IN_PROGRESS, with no confirm. It sits 12pt under Resume, and it is the only destructive action in the app that doesn't confirm.

**Fix:**
- Confirm with a destructive action sheet.
- Fix the backdrop while there: the Modal is `transparent` + `animationType="slide"` + a full-screen BlurView, so the blur slides up with the card. Fade the backdrop and slide only the card, or use an action sheet for the whole prompt.

Only the trigger changes, not the write.

### P3 — MUST — The Log Frames frame card jumps up and down on almost every throw [C]
*Source: A2-1*

`middleContent` uses `flexGrow: 1` + `justifyContent: 'center'` (`log-frames.tsx:1208`). These rows mount and unmount mid-frame and re-centre everything:
- the streak badge (all screens)
- the throw-note bar (Live + Quick)
- the Miss? chip row (~52pt; open screen only, since it is gated on height ≥ 760)

The "Frame N" card moves ~26pt and back during a frame.

**Fix:** anchor to the top (`flex-start`) or reserve fixed space for the conditional rows.

### P4 — MUST — The Reference tab resets itself on every visit [C]
*Sources: A5-1, A4-3*

## Batch 2 — Plumbing (Level 2: backup gate, reviewer pass, device checks)

### P13 — MUST (grows with data) — writeBackup is the biggest repeated cost in the app [C]
*Sources: A4-1, A3-4, A5-2*

`backup.ts:220` reads and parses the whole old file just for ids + count. `:245` / `:413` write pretty JSON:

| Sessions | Pretty | Compact |
|---|---|---|
| 46 | ~0.55 MB | 0.14 MB |
| 500, realistic | ~7–9 MB | ~2 MB |

It runs, with nothing coalescing:
- every cold launch
- every Log submit
- every History save / delete
- every Settings write, including each 600 ms goal pause
- every ball toggle
- every Reference blur / upgrade

**Fix:**
1. Compact JSON (restore reads either).
2. Single-flight with re-run-if-dirty and ~1 s coalescing.
3. Defer the launch run until after first paint.
4. *(L2)* Cache the last-written ids in memory, keyed on the file's `lastModified`, because the Files app can replace the file.

### P14 — SHOULD — Every delete / restore parses up to 10 kept copies [C]
*Source: A4-2*

`largestKept()` opens every `mBowl-kept-*` file (KEEP_KEPT = 10) just to pick the largest one to protect. It is fire-and-forget, so it doesn't block a tap.

**Fix:** put the session count in the filename. *L2:* `restoreForFirstLaunch` scans by prefix, so it stays safe.

### P15 — MUST (grows with data) — No parse cache; "did anything change?" is answered by re-stringifying everything [C]
*Sources: A4-4, A1-4, A3-2, A2-9*

- **On every Stats / History focus:** an AsyncStorage read, `JSON.parse`, validation, then `JSON.stringify` of all data, compared with the last signature (`StatsPage.tsx:1209-1221`, `HistoryPage.tsx:688-696`).
- **Repeated parsing:** sessions are parsed ~5× in a short session.
- **Memory:** each StatsPage copy keeps a full signature string. At scale that is MBs, in UTF-16 because of the `—` token.
- **Log Frames on the open screen:** it mounts a fresh StatsPage during the push and pays all of this.

**Fix:**
- In `readValidated`, cache by raw string (same raw string → same parsed object), then compare by identity.
- Fix History's in-place `raw.sort` (`:690`).
- Freeze cached objects in `__DEV__`.
- Prefer this over a revision counter, which would miss `backup.ts:346` `multiSet` and the `_layout` restores.

*L2:* write paths' fresh reads return shared objects. Only `:690` mutates.

### P16 — MUST (grows with data) — Data-change events reload Stats copies that aren't on screen [C]
*Sources: A4-5, A1-3, A2-10, A3-2*

StatsPage is mounted up to 4×:
- the Stats tab
- the Log second page
- the History second page
- the Log Frames side page

NativeTabs keep tabs mounted, and `PageVisibleContext` defaults to `true` (`page.tsx:72`). So the Stats-tab copy reloads and recomputes off-screen.

The listeners ignore `source` (`StatsPage.tsx:1237-1253`, `LogPage.tsx:519-524`, `HistoryPage.tsx:614-616`). A Reference blur re-reads all sessions everywhere, and after Submit the Stats tab reads twice (listener + focus).

**Fix:**
- Gate on `useIsFocused()`: mark dirty and reload on the next focus.
- Branch on `source`: `reference` → REFERENCE only; `settings` → settings only.
- After its own Submit, Log prepends the saved session instead of re-reading (keep `defaultHouseRef`).

### P17 — MUST (grows with data) — Reference saves on every blur even when nothing changed [C]
*Source: A5-2*

`save()` (`reference/index.tsx:363`, blurs at `:442 / :459 / :488 / :507`) has no dirty check. Each blur runs a REFERENCE write + a full backup (P13) + P16's reloads.

**Fix:**
- Compare before saving.
- Batch the backup.
- Also flush on AppState `background`: today, text typed in the last field is lost if iOS kills the app after backgrounding without a blur.

### P18 — SHOULD — Opening Settings parses the whole backup file to show one timestamp [C]
*Sources: A4-7, A3-5*

`backup.ts:555-565` → use `File.lastModified` (already used at `:521`). Minor: the sheet's first frame can show "No balls in roster" / the default seasons before its read lands.

### P19 — NICE — writeSessions stringifies twice [C]
*Source: A4-6*

`storage.ts:142-150`. *L2:* keep the order and the boolean semantics exactly.

### P20 — SHOULD — Every note keystroke in Log Frames writes the whole game to disk [P / device]
*Sources: A2-6, A2-13*

Each keystroke → a full re-render of the uncompiled screen + `framesKey` + `writeFramesInProgress`.

**Fix:**
- Debounce the in-progress write (~300 ms), with a flush on blur / background / unmount.
- Separately, `clearFramesInProgress` does `getItem` → `removeItem` without awaiting (`:845-847`), so it can overtake a later write. Chain the writes on that key.

*L2* (kill-safety path) → re-run the kill-and-reopen device checks.

## Batch 3 — Stats + compiler (Level 1)

### P21 — MUST (grows with data) — Trend charts remount every SVG node and don't scale [C / device]
*Sources: A1-1, A1-2, A6-3*

- **Remounts:** chart-kit keys every gridline / label / dot with `Math.random()`. It draws one vertical gridline per point and 2 circles per dot. That is ~310 nodes on All-Time today, ~3k at 500 sessions, remounted on every filter change and data reload. (Gear, sort and Show All taps are spared because StatsPage compiles.)
- **Game by game** plots every game, so the gridlines become a grey slab.
- **Series** labels every 3rd point, which probably overlaps on the cover screen already.

**Fix:**
- `withVerticalLines={false}`
- dots only when there are ≤ 30 points
- downsample to ≤ ~90 points (or a rolling average)
- label stride `ceil(n/5)`

Bezier smoothing doesn't overshoot (that sub-claim was cut), so keeping it is a taste call.

**[device]** Check Series label overlap on All-Time.

### P22 — SHOULD — The compiler skips the four most interactive screens [P]
*Sources: A2-3, A4-8, A3-14*

The bail-out causes:
- render-phase ref writes / reads: `LogPage.tsx:457`, `:473`; `log-frames.tsx:888`; `EditSessionModal.tsx:155`
- `eslint-disable react-hooks`: `LogPage.tsx:997`, `:1005`; `log-frames.tsx:619`; `SettingsContent.tsx:169`

Result: every Confirm, pin tap and keystroke re-renders the whole screen, and children get fresh closures that defeat their caches.

**Fix:**
- Move the ref writes into effects / handlers.
- Use `useEffectEvent` instead of the suppressions.
- Confirm with `npx react-compiler-healthcheck` (on the PC) or P39's lint.

### P23 — SHOULD — A filter tap's highlight waits for the full recompute [P]
*Source: A1-5*

Fine today. At 500 sessions on All-Time it's ~30–80 ms on Hermes.

**Fix:** `useDeferredValue` for season / type, and dim the content while stale. Do it after P21.

### P24 — SHOULD — Refocus with a non-default filter renders twice; cold start flashes "All-Time" [C]
*Source: A1-7*

`setLeaveSort` / `setTypeFilter` run before the `await` and `setSeasonSel` after it (`StatsPage.tsx:1202-1224`). That gives an intermediate view plus two heavy commits.

**Fix:** set all three together after the read, and hide the filter label until loaded.

### P25 — SHOULD — "Show all" leaves mounts every leave at once [P / device]
*Source: A1-8*

~15 views per leave. The `:1453` effect also collapses the list on any data reload and costs an extra commit.

**Fix:** reveal in pages of 20, and reset inside the filter handlers.

**[device]** Count the distinct leaves on All-Time.

### P26 — NICE today / SHOULD at scale — ~15 passes over every frame per filter change [C]
*Source: A1-10*

- Per-frame allocations to build leave keys (`leaveUtils.js:167-178`).
- `isSplit` DFS per frame in spareLeak (`spareLeak.ts:88-102`, `:171`).
- Measured 16 ms (JIT) at 500 sessions.

**Fix:**
- A 10-bit pin mask + a 1,024-entry split table.
- Optional: a per-game digest in a `WeakMap`.

### P27 — NICE — Stats small items [C]
*Sources: A1-6, A1-12, A1-13*

- The season comparison recomputes the selected season → reuse the memos.
- Cards that toggle to `null` shift content on a filter change → `animateNextLayout()`.
- Explanatory notes are `#48484A` 11pt (~2.3:1 contrast) → `color.dim`.
- Off-ramp sizes 13.5 / 10.5 / 12.5.
- Locked cards use 12pt spacing vs 20.
- Stale comment at `:1659`.
